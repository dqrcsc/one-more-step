## 已实现的行为

- 一个原生浮窗包含「最近投递」和「手机镜像」两个 Tab；右键菜单新增镜像直达入口。
- 镜像使用 WKWebView，复用 `/mirror` 页面、现有帧协议和输入接口。URL 来自主机实际配置端口，经原生校验后才加载。
- 打开 Tab 只加载页面，点击开始才建立手动观看连接；不自动唤醒/解锁。已有镜像运行时直接加入，正在启动时等待，不重复启动。
- 本窗口结束观看只释放自己的连接；多个观看端共用采集，最后一个离开 25 秒后主机尝试停止。手机离线时停止未确认不能等同于实际停播。
- 关闭、切 Tab、最小化、休眠、IPC 断开及 WebKit 页面进程退出都有释放路径；关闭不依赖 JavaScript 一定响应，原生会卸载旧页面。
- 输入等待对应 `reqId` 回执；手机明确拒绝或超时不报成功，文字失败保留。断线不改走 HTTP 重发输入，旧回执和旧解码不会污染新页面。
- 手机锁屏/安全窗口清除画面；画面超过 5 秒未更新时禁用普通控制；重连最多连续尝试 5 次。解锁仍需单独点击，并由现有服务端执行安全检查。
- 镜像失焦保持显示；投递页保留未钉住时收起。输入法组合输入不发送回车等手机快捷键。
- 页面使用内存网站数据存储；限定本机镜像导航，不允许外链、弹窗和下载。CSP 将 WebSocket 限定到同一主机端口。
- 安装脚本、daemon 自动编译及 `build:hud` 均链接 WebKit。兼容旧 HUD 忽略新字段，旧服务未提供 URL 时提示更新而非猜测端口。

## 验证与发现

完整 Bun 回归 **144 项通过、0 失败、931 个断言**；TypeScript 类型检查、Swift 原生构建及 diff 检查通过。

| 层次 | 实际验证内容 |
| --- | --- |
| 服务端 | 手动观看连接不自动采集；自定义端口；普通浏览器入口兼容；多观看者及最后一个离开的生命周期 |
| 页面真实脚本 + VM | 初始无连接、手动开始、退出不全局 stop、ACK 对应/拒绝保留文字、无 HTTP 输入重发、锁屏与迟到解码、输入法组合事件、启动取消和重连上限 |
| 真实 AppKit | 原窗口工厂、两 Tab 内容切换、非法/缺失 URL、空/1/25/30 条投递布局与选择状态 |
| 真实 WKWebView | 从随机 loopback 端口加载生产页面；合成 WebP 帧实际解码；手机模拟 ACK；失焦保留；切 Tab 后 WebSocket 关闭；重新打开不采集；外链拦截；最小化和页面进程退出处理 |
| 原生 Unix IPC | 新 URL 字段的真实 Swift 解码，发送/读取并行、断开重连和处理状态确认 |

WebKit 集成使用透明且不激活的测试窗口、合成帧与模拟回执，不读取或展示用户手机。测试服务器绑定随机端口；没有访问日常镜像服务。

实施中发现并验证了两项原生细节：

1. 退出不能只移除视图或等待 JS 完成；显式导航空白文档后，再检查导航已提交和观看连接关闭。
2. WebView 没有固有高度，AppKit 内容布局会把窗口压缩到接近标题栏高度。增加内容最小尺寸和明确的分隔线尺寸后，真实 WebKit 在 680×440 的窗口中显示完整画面区与输入控制栏；投递窗口回归仍通过。

详细测试日志保存在工作区 `one-more-step-analysis/reviews/2026-11-15/hud-mirror-tab/`，不包含用户手机内容。

## 后续部署方式

需要同时更新 Mac TypeScript 服务和 HUD 二进制，然后重启 Mac 主服务一次；不能只替换 HUD 就获得完整功能。更新前保留当前版本与二进制，以便整体回退。预计无需重新安装 APK或重新配对。

部署后可从菜单栏「手机镜像…」打开新 Tab；只有点击「开始镜像」才加入观看。推送或部署不自动启动真机验收。
