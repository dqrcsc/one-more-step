# Mac 浮窗超出屏幕：修复与验证

日期：2026-11-15。源码基线：`a372d1a`。

## 原因与复现

图片预览使用普通 `NSImageView`，其固有尺寸来自原图。即使设置等比缩放，Auto Layout 仍将这个尺寸向上传播为内容的期望尺寸，AppKit 因此放大窗口。投递页与镜像页共用窗口，隐藏投递页不会停用其约束，切换 Tab 也未恢复窗口大小。原有显示逻辑只居中，没有限制尺寸。

使用生产 Swift 窗口工厂、合成投递和合成 1200×6000 PNG，真实 AppKit 复现为 **1490×6234 点**的窗口；当时显示器可用区域为 **1792×980 点**。切换镜像 Tab 后仍为 1490×6234。空列表和 25 条普通文字没有复现超高，条数本身不是这个复现的原因。没有读取用户投递内容或手机画面，因此不能认定用户具体哪条附件触发了问题。

## 修改

- 预览图片视图不提供原图固有尺寸，由视口决定大小，保留等比缩放。
- 进入镜像 Tab 时移除隐藏详情的子视图，返回投递时重建，避免隐藏内容继续限制镜像尺寸。
- 附件操作栏改为横向滚动，窄窗口不会被所有按钮的总宽度撑大。
- 打开、切 Tab、切换所在显示器时限制最大窗口尺寸，并将位置校正到该显示器可用区域，避免遮挡菜单栏和 Dock。
- 关闭语义保持：Esc、关闭按钮和最小化释放本窗口 WebView；切 Tab 不关闭其他浏览器观看端；镜像失焦保留显示。

## 验证

完整 Bun 回归 **144 项通过、0 失败、931 个断言**。类型检查、Swift 正式二进制编译通过。

真实 AppKit 使用透明、不激活的合成窗口，验证：

- 同一张长图保持 840×560 点；不会按图片像素撑高或撑宽。
- 查看长图后切换镜像，可缩至 680×440 点，隐藏详情不再影响最小尺寸。
- 返回投递后窄窗口内按钮行可横向滚动，关闭按钮确实位于滚动文档内。
- 对一个带偏移的 1024×700 可用区域进行尺寸和位置校正。
- Esc、关闭按钮隐藏窗口，关闭后可复用原窗口再次打开。

真实 WKWebView 使用随机 loopback 端口、合成 WebP 和模拟回执，验证最小窗口中的画面与控制栏、切 Tab 断开观看、重新进入保持未开始状态、失焦、最小化、页面进程退出，以及 Esc/关闭按钮释放 WebView。未访问日常手机镜像流。

界面自动化工具无法定位独立的 `oms-mac-hud` 可执行进程，本轮没有直接拖动或点击日常浮窗。上述结果来自生产代码的原生集成测试；真实多显示器拖动、显示缩放切换、中文输入法和手机真机画面仍待人工验收。

## 本地更新

已更新运行目录的 `mac-host/mac-hud/main.swift` 和 HUD 二进制，保留旧文件备份并重启浮窗助手；主服务与蓝牙桥进程保持运行。更新后已核对新 HUD 与原主服务的 IPC 连接，镜像未运行且观看连接数为 0；不需要重装 APK 或重新配对。
