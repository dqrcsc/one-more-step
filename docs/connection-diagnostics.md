# 连接诊断（v1.4.1）

手机首页连接状态下方的 **连接诊断** 在离线时也可打开。点击 **复制诊断** 后，可手动粘贴给排查者。内容包括采集时的链路、物理 Wi-Fi 是否可用、锁屏状态、手机 IPv4、已保存的 Mac IPv4，以及最近连接事件。IP 是排查所需的局域网元数据；复制不会自动外发。

## 提示如何解释

| 提示 | 观察到了什么 | 下一步 |
|---|---|---|
| 未检测到 Wi-Fi | 没找到物理 Wi-Fi 网络 | 连接与 Mac 可互通的网络 |
| 暂时无法访问 Mac | 保存地址和发现探测未找到已绑定主机 | 检查服务和网络，浏览器访问 Mac HTTP 页面做对照 |
| 连接 Mac 超时 / 无法建立连接 | 建立连接失败 | 检查网络、服务和防火墙；不能据此直接归因为 AP 隔离 |
| 与 Mac 的连接已断开 | 已有连接关闭或发送失败 | 等待自动重连；持续失败先复制诊断 |
| 安全握手超时 | 传输建立后未按时完成认证 | 检查两端版本和网络稳定性；不自动清除配对 |
| 安全校验未通过 | 协议或认证检查拒绝了连接 | 保留现场并复制诊断；不代表一定丢失密钥 |

自动重试期间保留上一次失败原因，恢复后清除；备用链路失败不覆盖 LAN 原因。日志事件为历史，重启后不把上一次在线状态当成现在仍在线。诊断面板在打开时采集一次，重新打开可刷新。

## 日志范围

- 手机：应用私有目录 `connection-diagnostics.log`，最多 200 条；同链路连续相同事件在 30 秒内合并。UTC 时间、固定事件码、链路和本地 LAN 尝试编号；不是协议会话 ID。
- Mac：`~/.one_more_step/logs/connections.jsonl`，最多 200 条；UTC 时间、固定事件码、本机随机连接编号、WebSocket 数值关闭码。`oms status` 返回 `connectionDiagnostics`，包含这些事件和文件持久化状态。
- 不写配对 URI、token、密钥、消息正文、屏幕、远端关闭原因或原始异常消息。日志文件失败不会阻断连接；手机提示仅内存记录，Mac 返回 `persistenceAvailable=false`。
- 日志只保留最近事件，不是审计归档或可靠断电事务。旧版运行期间的故障不能事后还原；长期锁屏、AP 漫游和蓝牙/WAN 原因仍需对应环境验证。

## 升级与验证

v1.4.1/code15 沿用 v2 协议和既有签名，覆盖安装无需重新配对。此修改增加可观测性，不改变认证、重试或网络策略，也不修复路由器的设备隔离。

自动测试覆盖原因保留/恢复、备用链路隔离、历史加载、日志上限、敏感异常排除、Mac 会话关联与拒绝路径。本机真机已验证诊断入口、复制内容、关闭 Wi-Fi 时提示及恢复后原因清除；详情见 [v1.4.1 验收](ota-1.4.1.md)。其他设备与网络环境需要单独验证。
