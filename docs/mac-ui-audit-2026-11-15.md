# Mac 界面交互复核

日期：2026-11-15。基线：`3bb4349`。只使用 Mac 合成数据及模拟服务；手机真机测试继续暂停。

## 复核范围与成功标准

检查菜单与窗口入口、投递详情刷新、图片查看缩放和窗口层级、镜像文字提交及既有关闭行为。优先复现问题，避免扩大到未出现的需求。

成功标准：后台刷新不打断正在阅读的未变化内容；重复提交只发出一次文字请求；失败/旧会话不能丢失草稿；图片手势缩放后不被窗口调整重置；既有最大高度、置顶、关闭与手动开始规则不回退。

## 已复现并修复

1. **详情刷新打断阅读**：`sync_items`/新投递会重新创建当前详情，清空选择、滚动状态并停止音频。AppKit 合成复现确认同一内容的视图对象被替换。现在后台刷新只在当前条目或附件索引发生变化时重建详情；侧栏照常更新。主动选择/重开仍允许刷新。
2. **镜像文字重复提交**：首次回执前再次提交会产生第二个请求；隔离测试原来收到两条文字请求。现在同一时间只允许一条文字提交，提交按钮禁用但草稿仍可编辑。回执、拒绝或超时结束后恢复；退出会话清理等待状态，旧会话回执不清空草稿。
3. **图片手势缩放被重置**：将缩放比例手动设为 0.7 并模拟手势结束后，窗口调整使其变为约 0.1513。现在接收原生手势结束通知，将其视为用户手动缩放；窗口调整保留该比例，“适应窗口”可以显式恢复自动适配。
4. **状态文字混淆**：原详情根据 `processed` 显示“未读”，即使已打开仍显示未读。改为“待处理”，不改变实际处理状态或菜单栏的未读集合。

## 核验通过而未修改的行为

- 图片子窗口实际会跟随父窗口层级：未置顶时两者均为普通层（0），没有根据孤立的初始化代码误判并修改。
- 图片窗口在 360×280 内容区内，工具栏边界约为 x=22、宽316.5，按钮未越界。
- 既有镜像手动开始、切 Tab 释放、最小化恢复不采集、Esc/关闭清理、原生置顶状态、最大高度、长图与窄窗口回归通过。
