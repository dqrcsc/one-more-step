## 本轮新增发现

### 1. P2：收藏入库缺少幂等性，网络重试会生成重复笔记

- 验证：已使用现有 `MobileMemoryMirror.promoteToVault()` 和临时目录复现。
- 位置：`mac-host/src/memory/mobile-memory-mirror.ts:202–238`；手机重试入口为 `android-app/app/src/main/java/com/oms/client/cockpit/CockpitRuntimeCoordinator.kt:729–758`。
- 触发：Mac 已写入笔记，但手机未收到成功响应，手机把同一 itemId 加入待重试队列。Mac 收到重试后，没有查找 itemId 对应的既有结果，而是分配带新后缀的文件名。
- 复现结果：同一个 itemId、相同请求连续调用两次，生成 `2026-11-21_重试验证.md` 与 `2026-11-21_重试验证_2.md`。这与不同 itemId 同标题时避免覆盖的需求不同。
- 最小修复方向：持久保存 itemId 对应的写入结果，重试返回原路径；对同一 itemId 的不同内容明确拒绝或制定更新规则。恢复逻辑也要覆盖“文件写入成功、结果登记之前中断”的情况。
- 验收：成功响应丢失、进程重启后重试同一个操作，仍只有一篇笔记和一套附件；不同 itemId 的同名收藏仍保留各自文件。

### 2. P2：Mac 中文历史搜索漏掉句中的短语

- 验证：已直接调用现有 `syncBatch()`、`searchContext()` 复现。
- 位置：`mac-host/src/memory/mobile-memory-mirror.ts:247–289`。
- 原因：默认 FTS5 搜索未命中时不会抛异常，而 LIKE 补充查询只在 catch 中执行。连续中文文本中的部分短语因此不能被召回。
- 复现结果：存入“我们正在推进门店销售异常诊断项目”；搜索“门店销售”返回 0 条手机聊天结果，搜索整句返回 1 条。数据已经存在，问题在检索。
- 最小修复方向：FTS 结果不足时补充有界的中文子串查询，并按消息 ID 去重。Android 已有类似补充逻辑，可以保持两端行为一致；不必立即引入新的检索服务。要控制 LIKE 扫描成本并明确是否按最近记录限定范围。
- 验收：两字或多字中文子串可召回，英文 FTS 仍有效，补充结果不重复且遵守 limit；用较大测试库检查延迟。

### 3. P2：重连只同步一批，积压数据不会自动排空

- 验证：静态调用链确认，未运行 Android 测试。
- 位置：`android-app/app/src/main/java/com/oms/client/cockpit/CockpitRuntimeCoordinator.kt:745–762`；`ChatMemoryRepository.kt:460–499,552–555`。
- 触发：手机离线积压超过 40 条完成消息，或超过 20 条收藏；重连且后续没有新对话、前台切换或链路变更事件。
- 原因：每次 flush 仅执行一次 `exportUnsyncedBatch(40)`，收藏也仅查询一次 LIMIT 20。成功确认后没有继续取下一批，也没有本函数安排的续传。若启动时多个事件触发了 flush，可能多发几批或重复同一批，但不能保证最终排空。
- 最小修复方向：串行执行同步，成功后继续读取下一批；以数量或时间预算控制每轮工作量，未排空时安排后续执行。失败和断线应退出并保留待发记录，避免忙循环。
- 验收：离线创建 125 条完成消息和 45 条收藏，只触发一次同步请求即可最终发完；过程中断线可继续；多个入口同时触发不会重复处理同一批。

### 4. P2：旧批次确认会把发送期间的新修改标成已同步

- 验证：静态调用链确认，未运行 Android 测试。
- 位置：`android-app/app/src/main/java/com/oms/client/cockpit/ChatMemoryRepository.kt:187–195,531–538`；`CockpitRuntimeCoordinator.kt:749–752`。
- 触发：先导出标题 A 并开始 RPC；等待期间用户改为标题 B，rename 将 synced_to_mac 置 0；随后 A 的成功响应到达，markBatchSynced 只按 thread_id 把当前记录标为 1。
- 影响：Mac 保存 A，手机保存 B，但手机认为已经同步，后续没有别的修改时不会再导出 B。消息更新也使用按 ID 确认的相同模式。
- 最小修复方向：导出时记录本地修订号，确认时仅更新修订号仍相同的记录。rename/pin 当前不会更新时间，因此仅拿现有 updated_at_ms 比较还不足以覆盖所有修改。
- 验收：同步响应延迟期间重命名、置顶或更新消息，旧 ACK 不能清掉新版本的待同步状态；下一批应把新版本发送到 Mac。
